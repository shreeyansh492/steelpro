A

System architecture

Public traffic never reaches the file server. The backend authorises the request first, then pulls the file across the VPN and streams it to the browser. SMB stays inside the company network.

Postgres holds the index, not the drawings

Document ID, project ID, file name, type, revision, status, path, uploaded by, upload date, review status. A row is worth a few hundred bytes; the DWG behind it stays on the file server.

Files only move through the tunnel

The VPS mounts nothing permanently. Each read is an authorised, logged fetch over WireGuard, with the resolved path built by the app rather than sent by the browser.

Nothing inbound to the file server

The firewall accepts the tunnel and nothing else. SMB/445 is never published, and a stolen session token still cannot reach a path outside its own project folder.

B

Two portals, one backend

The same data, filtered by who is looking. Switch roles and move through the screens — the navigation is live.

Streamed, never linked

The viewer asks the API for the file. The API checks the session, the project and the document, then pulls the PDF over the VPN. The browser never sees a file server path.

A decision closes a revision

Submitting a review writes the outcome against R3 and opens R4 in the register. R3 stays exactly as it was issued, comments and all.

Pins carry coordinates

Each pin stores page, x/y on the sheet and the grid reference the detailer reads. The PM sees them on the same drawing, in the same place.

F

Security posture

Two things protect the drawings: the tunnel, and the authorisation check that runs before anything is read from it.

  • HTTPS everywhereTLS 1.3 at Nginx, HSTS, modern ciphers only.
  • Short-lived JWTs15-minute access token, rotating HttpOnly refresh token.
  • Role-based accessAdmin, PM, detailer, client — resolved server side.
  • Project scopingEvery query filters by the client the user belongs to.
  • Document authorisationChecked per document and per revision, not per folder.
  • Argon2id hashingPer-user salt, tuned work factor, no password ever emailed.
  • Audit logViews, downloads, uploads, reviews and stage changes, with IP.
  • Rate limitingPer IP and per account on login, upload and download.
  • Upload validationExtension and magic-byte check, 150 MB ceiling, AV scan before filing.
  • Encrypted tunnelWireGuard or IPsec, keys held on the VPS and the firewall only.
  • No public SMBPort 445 never leaves the company network. No inbound rule exists.
  • BackupsNightly Postgres dumps, nightly file replication, weekly offsite copy.

What a client can reach

A signed-in client sees the projects belonging to their company and nothing else — not a project list, not a search result, not a document ID guessed from a URL. The check happens on the server for every request, including the one that streams a PDF into the viewer. Downloads follow the company policy set per client: approved revisions only, or view-only throughout.
